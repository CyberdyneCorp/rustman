Your API workbench belongs in your repo.

Rustman is a local-first API client and test runner written in Rust. One native binary gives you a terminal UI for exploring, a CLI for CI and an MCP server for AI agents. Requests are plain YAML files you review in pull requests. No account, no telemetry, no seat limits.

Three front-ends, one engine

The same request files, wherever you work

Explore in the terminal UI, run the same files in CI, let an agent drive them through MCP, and open the optional companion when you want charts.

rustman tui

A full workbench in your terminal

Collections in a sidebar, requests in tabs, responses as collapsible trees, a timing waterfall, a command palette and an environment switcher with secrets masked. It runs over SSH.

rustman            # opens the TUI
rustman tui api/   # on a workspace
ci

The same files in CI

JUnit, TAP, SARIF, HTML and JSON reports, data-driven runs and exit codes that stay stable across 1.x. It replaces newman run line for line.

rustman run . --env staging \
  --reporter junit:out/junit.xml \
  --reporter pretty
rustman mcp

An API workbench for your AI agent

A built-in MCP server lets Claude Code and IDE agents send requests, run collections and explore specs, read-only unless rustman.toml allows more. It can also inspect and test other MCP servers.

rustman mcp serve
rustman-viz

Dashboards when the terminal isn't enough

The optional native companion draws run, exploration and bench dashboards and a response inspector. It is read-only and never sends requests.

rustman run api/ --viz
Beyond sending requests

Everything around the API, built in

Mocks, load tests, contract checks and docs usually need four more tools. In Rustman they all read the request files you already have.

Tests from an OpenAPI spec

Point it at a spec and it plans and runs a campaign: conformance, auth, injection and undocumented behavior, under a safety policy.

Load and stress

bench for load, stress to find the breaking point with spikes, soak, fuzzing, wire faults and recovery checks.

Contracts and snapshots

OpenAPI breaking-change diff in CI, Pact generate and verify, and snapshot assertions for whole responses.

Mocks, docs, monitors

A mock server from OpenAPI, a static docs site from your requests, and monitors run by cron or CI. No call quotas.

Traffic recorder

A recording proxy with a per-workspace local CA turns real traffic into request files and HAR, with secrets detected.

Trace propagation

W3C and B3 context on every request, trace links in reports and OTLP export, so you can follow a call into your backend.

Ethereum console

ABI-aware calls and decoded logs, provider probing, subgraph presets, Anvil forks and a signing gate agents can never pass.

WASM plugins

Auth schemes, assertion functions, generators and importers as sandboxed components with a frozen API and pinned hashes.

Only in Rustman

What you gain

  • Requests as codeYAML next to your source, diffed and reviewed like everything else.
  • A terminal-native workbenchA full TUI that works over SSH, without leaving the keyboard.
  • Autonomous OpenAPI testingFindings with evidence and a curl command to reproduce each one.
  • Stress testing that finds the breakBreakpoint, spike, soak and fuzz modes with recovery checks.
  • Contracts you can rely onRequest files, reports, the plugin API and exit codes are frozen for 1.x, each guarded by a test.
  • Signed releasesEvery archive carries Sigstore build provenance you can verify with gh attestation verify.
Where Postman is still ahead

What you give up

  • A graphical appPostman's GUI is easier for people who don't live in a terminal.
  • JavaScript scriptingNo script engine, by design. Imported checks become assertions; other logic moves to WASM plugins.
  • Real-time collaborationShared cloud workspaces, comments and roles. Rustman uses Git instead.
  • Hosted servicesPostman runs mocks and monitors in its cloud; with Rustman you run them in CI or on a server.
  • Visual workflowsPostman Flows has no Rustman equivalent.
  • Ecosystem sizeA decade of integrations, tutorials and answers.
Switching

Move a Postman collection in three commands

The importer reads Collection v2.0 and v2.1, moves secret values to the OS keychain and converts pm.test checks to assertions. The migration guide covers the rest, including what doesn't carry over.

Step 1

Create a workspace

rustman init my-api
cd my-api

Writes rustman.toml, a local environment and a sample request.

Step 2

Import

rustman import postman-env \
  staging.postman_environment.json
rustman import postman \
  shop.postman_collection.json

Secrets go to the keychain, never into files.

Step 3

Run it in CI

rustman run . --env staging \
  --reporter junit:out/junit.xml

Replaces newman run. Exits 1 on a failed check.
