# Rustman documentation

User and developer documentation for Rustman. Pages are added as the features they describe are implemented; the behavior itself is specified in [`openspec/`](../openspec/).

## Available

- [Install and quick start](../README.md#install-and-quick-start-current-state)
- [Request files](request-files.md): the workspace layout, `rustman.toml`, the `*.rman.yaml` format with one example per body type, collections and `rustman init`
- [Environments, variables and secrets](environments.md): environment files, the active environment, variable precedence, dynamic variables, `rustman secret`, secret storage and redaction, and the CI pattern
- [Secret providers](secrets.md): `{{secret:<provider>/<path>#field}}` references and provider-backed environment variables, resolution at send time only, `[secret_providers.*]` in `rustman.toml` and the user config (no credentials, no commands in the workspace), the `keychain`, `env`, `sops` (age, PGP via `gpg`), `onepassword` (`op` CLI, Connect), `vault` (KV v1/v2, token, AppRole, OIDC), `cmd` and cloud provider types, timeouts, the in-memory cache and Refresh secrets, failures and exit codes, redaction, `rustman secret get|test|list-providers`, and agents
- [Safety policy](safety.md): the rules automated senders (exploration, agents) pass before a request is sent: method gating, the origin allowlist, the production guard, rate, concurrency and budgets, `429` backoff, the `[safety]` table in `rustman.toml`, and `GovernedSender`
- [HTTP requests](http.md): transport, timeouts, redirects, TLS and mTLS, proxies, cookie jars, default headers, auth helpers (including OAuth2 and `rustman auth login`), timings, response bodies, and `rustman import curl` / `rustman export curl`
- [Code snippets](snippets.md): `rustman export snippet` for curl, HTTPie, wget, Python, JavaScript, Go, Rust, PowerShell and C#, redaction and `--show-secrets`, signature-auth helpers, placeholder mode and GraphQL requests
- [Signature auth](auth.md): Digest (challenge, nonce reuse, replayable bodies), AWS SigV4 (credential sources, redirects, unsigned payloads, clock skew) and JWT (algorithms, keys, claims, placement, redaction)
- [OpenAPI import](import-openapi.md): `rustman import openapi` for OpenAPI 3.0/3.1 files and URLs, format and version detection, `$ref` resolution and `--allow-remote-refs`, validation diagnostics with JSON pointers, the generated collection layout, example bodies and the schema synthesizer, servers as environments, security schemes as auth with secret placeholders, the import snapshot, and `--sync` (three-way merge, `_removed/`, the change summary, `--json`, `--dry-run`)
- [OpenAPI exploration](exploration.md): `rustman explore plan`, `run`, `status`, `resume` and `export`, dependency discovery (links, heuristics, `[explore.producers]`), the probe families, seeded fuzzing, the finding rules and their severities, cleanup and resources left behind, the exploration report and coverage, reproducing findings as curl and regression request files, Ctrl+C and resume, exit codes, `[explore].disabled_rules`, and the `bad-api` fixture
- [GraphQL](graphql.md): `kind: graphql` request files, their fields and defaults, interpolation (never inside the document), introspection and its legacy fallback, the schema cache in `.rustman/graphql/schemas/`, `schema_file` and `[[graphql.endpoints]]`, how the schema is chosen, validation, sending over HTTP (GET, uploads, APQ), subscriptions over WebSocket (`graphql-transport-ws` and the legacy protocol) and SSE with their headless limits, GraphQL assertions and captures, history records, `kind: graphql` in `rustman run`, `rustman graphql introspect` / `query`, and the TUI GraphQL editor
- [JSON-RPC](jsonrpc.md): `kind: jsonrpc` envelopes and id handling, notifications, response classification and errors, batches matched by id, timeouts, retries for idempotent calls, the WebSocket transport and its per-run connection reuse, and generic subscriptions with their headless bounds, the `rpc_error` assertion and envelope-wide JSONPath assertions and captures, history records with redacted params, OpenRPC catalogs (`[jsonrpc.catalogs]`, the cache, validation and `--no-validate`), `rustman rpc call` / `batch` / `discover`, `kind: jsonrpc` in `rustman run` and its JSON report, the TUI editor, method guards and the agent `rpc_call` tool
- [gRPC](grpc.md): `kind: grpc` request files and their fields, interpolation and metadata redaction, schema sources (server reflection v1 with the v1alpha fallback, `.proto` files compiled in-process, descriptor sets), path containment and compile errors, the descriptor cache in `.rustman/grpc/descriptors/` and offline browsing, the method browser with its message templates, message encoding and unknown-field errors, unary and streaming calls with the message timeline, headless stream bounds, deadlines, binary metadata, TLS, mTLS and h2c, gRPC-Web, rich status details, the `grpc_status` and `metadata` assertions and `from: metadata` captures, `kind: grpc` in `rustman run` and history, `rustman grpc list` / `describe` / `call` / `health` with their exit codes, the TUI gRPC editor, and the agent tools `grpc_list`, `grpc_describe` and `grpc_call`
- [WebSocket and SSE](realtime.md): `kind: ws` and `kind: sse` sessions, the WebSocket handshake (headers, auth, subprotocols, TLS, proxies, refused upgrades), scripted steps (`send`, `wait_for`, `sleep`, `close`), ping/pong and close handling, SSE streams over GET and POST and their WHATWG parsing, reconnect and resume with `Last-Event-ID` and `retry`, the message timeline, headless bounds and size limits, the `messages` and `close_code` assertions with JSONPath over `$.messages`, the `realtime` history and report record, `rustman ws connect` / `rustman sse listen`, the TUI realtime editor and the agent `realtime_listen` tool
- [Messaging](messaging.md): `kind: kafka`, `kind: mqtt` and `kind: amqp` request files (`operation: produce|consume`, brokers, destinations, `limits`, `start`, `tls`, `auth`), message payloads (text, compact JSON, base64, workspace files), Kafka produce (explicit partition, Java-compatible murmur2 key hashing, round robin, `acks`) with recorded partitions and offsets, Kafka consume by partition and offset (`earliest`, `latest`, absolute, timestamp) with no consumer group and no commits, bounded memory, TLS and SASL PLAIN/SCRAM with redacted passwords, Schema Registry decoding and encoding (Avro, Protobuf, JSON Schema) with a per-run cache, client limitations; MQTT 3.1.1/5 publish and subscribe (QoS 0-2, retain, MQTT 5 properties, wildcards, clean sessions, TLS, mutual TLS, WebSocket); AMQP publish with confirms and `mandatory`, temporary-queue consume, named queues with `destructive` or `requeue`; AsyncAPI 2.6/3.0 import and payload validation; runs with headless bounds, `start: before_next`, assertions and captures over consumed messages and history with 64 KiB previews; safety gating of produce and named-queue consume for agents; `rustman kafka|mqtt|amqp produce|consume`; the TUI messaging pane; and the broker tests
- [Agents (MCP server)](agent.md): `rustman mcp serve` for Claude Code, Claude Desktop and other MCP clients, stdio and Streamable HTTP (loopback bind, bearer token, Origin check), the `[agent]` table, the read-only default and human confirmation of mutations, redaction of results, output limits and `rustman://bodies/`, the audit log, background jobs (progress, cancellation, resume), the generated tool reference, and the tool error codes
- [MCP client](mcp-client.md): MCP server definitions (`[mcp_servers]` in `rustman.toml` and `mcp/servers/*.yaml`), interpolation, workspace trust for stdio commands (`.rustman/trust.yaml`, `--trust`), the stdio, Streamable HTTP and legacy HTTP+SSE transports, initialization, version negotiation and capabilities, tools (schema forms, argument validation, results, `outputSchema`), resources and templates, prompts and completion, notifications, progress, timeouts and cancellation, sampling, elicitation and roots, OAuth, `kind: mcp` request files (assertions, captures, runs with one session per server, history), `rustman mcp-client` and the TUI MCP inspector
- [Assertions and captures](assertions.md): status, header, JSONPath, JSON Schema, body and latency assertions, interpolated expected values, captures, and where captured values are kept
- [Snapshot testing](snapshots.md): the `snapshot` assertion and its full form, where snapshots are stored, the snapshot file format, compared parts and the header include list, normalization (secret redaction, `ignore`, presets, `replace`, `sort`) and its fixed order, JSON, text and binary diffs, event-list snapshots, recording, update and CI modes, and reviewing failures in the TUI (Snapshot tab, `a` approve, `r` reject, `Alt+A` queue)
- [Trace propagation](tracing.md): the `trace:` environment block and `[trace]` in `rustman.toml`, `--trace`, W3C `traceparent`/`tracestate`, B3 single and multi, `baggage` with variables, `scope: run`, headers you set yourself, signed requests, the request kinds covered, recorded trace ids, `traceresponse` and `Server-Timing`, link templates and presets, `rustman trace open` and the TUI `Ctrl+O`, OTLP export of client spans (`[trace.export]`, the `otlp` build feature)
- [Request history](history.md): what is recorded and where, retention, redaction at rest, `rustman history list` filters, `show`, `replay` with secret re-resolution, and `clear`
- [Importing collections](import.md): `rustman import` for Postman collections and environments, Insomnia exports, Bruno collections, HAR captures and `.http` files: format detection, the destination, dry runs, secret extraction, script handling and Postman script migration, deterministic names, the conflict policy, the import report and exit codes; and `rustman export postman` / `rustman export http`
- [API docs](api-docs.md): `rustman docs build` and the `rustman docs serve` live-reload preview, the `[docs]` table in `rustman.toml`, the `docs:` key of request files, the generated site (sections, endpoint pages, OpenAPI enrichment, search, themes), opt-in examples from history or snapshots, code samples and custom sample templates, Markdown output, GraphQL schema and JSON-RPC method references, redaction and the leak scan, publishing variables, layout template overrides, the output folder and its manifest, and publishing to GitHub Pages
- [CLI reference](cli.md): every command, global flags, `rustman send` (including ad-hoc requests), `rustman run` (filters, iterations, parallel folders, bail), the pretty, json, junit and tap reporters, terminal output and logs, completions and exit codes
- [Data-driven runs](data-runs.md): `rustman run --data` with CSV and JSON rows, a collection's default data file, row variables and their precedence, iteration labels in reports, `--bail=iteration` and secret columns
- [Reports](reports.md): the canonical `rustman.report/v1` report of runs and explorations, `rustman report schema`, `render` and `diff`, `--report <format>[=<path>]`, the JSON, JUnit, SARIF, Markdown and HTML formats with examples, redaction, and CI recipes (GitHub code scanning)
- [Load testing](bench.md): `rustman bench` for request files and collections, iterations and virtual users, the `constant-vus`, `ramping-vus` and `constant-arrival-rate` executors, think time and stages, open and closed models and coordinated-omission correction, data feeding (`sequential`, `per-vu`, `random`, `stop` and `recycle`), the safety policy pinned to `--target`, the `[bench]` caps in `rustman.toml`, metrics and the per-second series, thresholds (`--threshold`, `[bench.thresholds]`, abort-on-fail `!`), Ctrl+C, generator lag, the live dashboard and progress lines, `--viz` streaming, JSON and HTML reports, redaction, the summary, error classes and exit codes

- [Plugins](plugins.md): WebAssembly component plugins, the plugin package and `rustman-plugin.toml`, `rustman plugin add|list|remove|verify|api|test|new`, declaring plugins in `rustman.toml` (`source`, `sha256`, `grants`, `limits`), sha256 pinning and `rustman.lock`, URL sources and their cache, the grant vocabulary, the sandbox (no ambient WASI, files, network through the safety policy, secrets as handles, logs), CPU and memory limits and fault isolation, plugin API versions, the `rustman-plugin-sdk` bindings and project templates, and the host test harness with its fake clock, randomness, network and secrets
