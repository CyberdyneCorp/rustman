## ADDED Requirements

### Requirement: Build command
`rustman docs build` SHALL generate documentation from the current workspace into `--out` (default `site/`), as `--format html` (the default), `markdown` or `both`. It SHALL replace only files it generated, tracked in a `.rustman-docs-manifest`, and SHALL refuse a non-empty output directory without that manifest unless `--force` is given.

#### Scenario: Default build
- **GIVEN** a workspace with two collections and five requests
- **WHEN** the user runs `rustman docs build`
- **THEN** `site/index.html` SHALL exist with one section per collection and one endpoint page per request

#### Scenario: Unrelated output directory
- **GIVEN** `site/` contains files and no `.rustman-docs-manifest`
- **WHEN** the user runs `rustman docs build`
- **THEN** it SHALL fail with `site/ is not empty and was not generated by rustman docs; use --force` and exit code 2

### Requirement: Structure follows the workspace
Collections SHALL become sections and nested folders subsections, in the workspace order from `workspace`. Requests SHALL become endpoint pages. Collection `description` and request `description` SHALL be rendered as CommonMark. Requests with `docs: {hidden: true}` and the `.rustman/` directory SHALL be excluded.

#### Scenario: Hidden request
- **GIVEN** `debug.rman.yaml` with `docs: {hidden: true}`
- **WHEN** docs are built
- **THEN** no page, navigation entry or search entry SHALL exist for it

#### Scenario: Collection order
- **GIVEN** a collection whose `_collection.yaml` sets `order: [login, list]`
- **WHEN** docs are built
- **THEN** the navigation SHALL list `login` before `list`

### Requirement: Endpoint page content
Each `http` endpoint page SHALL show:
- the method and URL template with variables kept as `{{name}}`;
- tables for query parameters, headers and body fields;
- the body type;
- the auth scheme name (never credentials);
- the assertions as "expected behavior";
- the captures as "produces".

#### Scenario: Page tables
- **GIVEN** `POST {{base_url}}/users` with header `Content-Type: application/json`, a JSON body `{name, role}` and `- status: 201`
- **WHEN** its page is built
- **THEN** it SHALL show `POST {{base_url}}/users`, a headers table with `Content-Type`, a body table with `name` and `role`, and "Expected: status 201"

### Requirement: OpenAPI enrichment
When the workspace contains an OpenAPI import snapshot from `openapi-import`, each request generated from an operation SHALL also show the operation's summary, description, parameter descriptions and request/response schemas, plus a `deprecated` badge when flagged. Request-file descriptions SHALL take precedence over OpenAPI descriptions.

#### Scenario: Deprecated operation
- **GIVEN** a request generated from an operation with `deprecated: true`
- **WHEN** docs are built
- **THEN** its page and navigation entry SHALL show a `deprecated` badge

#### Scenario: Description precedence
- **GIVEN** an operation description "List users" and a request-file description "Lists active users only"
- **THEN** the page SHALL show "Lists active users only"

### Requirement: Real examples are opt-in
A request SHALL show a recorded example only when its file sets `docs: {example: true}` or `[docs].examples` lists it. The example SHALL be the latest successful exchange from `request-history`, or the stored snapshot when `snapshot-testing` is present and `--examples snapshot` is given. Requests without an opted-in example SHALL show schema-derived samples only.

#### Scenario: Not opted in
- **GIVEN** a request with history but no `docs.example` flag
- **WHEN** docs are built
- **THEN** no recorded response SHALL appear on its page

#### Scenario: Opted in
- **GIVEN** `docs: {example: true}` and a recorded `200` exchange
- **WHEN** docs are built
- **THEN** the page SHALL show that response's status, selected headers and pretty-printed body, labeled with its recording date

### Requirement: Redaction in generated docs
Every value written to the site SHALL pass the `environments` redaction step. Secret values SHALL appear as `«redacted:name»`. Headers `Authorization`, `Cookie`, `Set-Cookie`, `Proxy-Authorization` and `X-Api-Key` in examples SHALL be redacted even when no secret matches them. The build SHALL fail with exit code 1 if a known secret value is found in any output file.

#### Scenario: Token in an example body
- **GIVEN** an opted-in example whose response body contains the secret `token` value
- **WHEN** docs are built
- **THEN** the body SHALL show `«redacted:token»`

#### Scenario: Post-build leak scan
- **GIVEN** a custom template that prints a raw secret
- **WHEN** docs are built
- **THEN** the build SHALL fail with `secret value found in site/<file>` and exit code 1, and SHALL NOT leave that file in place

### Requirement: Environment values are not published by default
Variables SHALL be rendered by name only. A variable's value SHALL appear only when it is listed in `[docs].publish_variables`, which SHALL reject secrets with exit code 2. `--env <name>` SHALL select which environment's publishable values to show, defaulting to none.

#### Scenario: Base URL by name
- **GIVEN** no `publish_variables`
- **WHEN** docs are built
- **THEN** URLs SHALL read `{{base_url}}/users`

#### Scenario: Publishing a secret refused
- **GIVEN** `publish_variables = ["token"]` where `token` is a secret
- **WHEN** docs are built
- **THEN** it SHALL fail with `token is a secret and cannot be published` and exit code 2

### Requirement: Code samples
Each endpoint page SHALL include code samples for curl, HTTPie, JavaScript `fetch`, Python `requests` and Rust `reqwest`, generated from templates with variables kept as placeholders and secrets as `«redacted:name»`. `[docs].samples` SHALL select and order languages. `[docs].template_dirs` SHALL override or add templates by language id.

#### Scenario: Default samples
- **WHEN** a page is built with default settings
- **THEN** it SHALL show tabs for `curl`, `httpie`, `fetch`, `python` and `rust`, in that order

#### Scenario: Custom language
- **GIVEN** a template `templates/go.tmpl` in a configured template dir and `samples = ["curl", "go"]`
- **WHEN** docs are built
- **THEN** each page SHALL show only `curl` and `go` samples

### Requirement: Self-contained offline site
The HTML site SHALL make no network requests when opened: every CSS, JS, font and image SHALL be in `--out` or inlined, and pages SHALL work over `file://`. Navigation and content SHALL render with JavaScript disabled; only search and the theme toggle need JavaScript.

#### Scenario: No external references
- **WHEN** the site is built
- **THEN** no output file SHALL contain an `http://` or `https://` URL in a `src`, `href` (other than links written in user content) or CSS `url()`

#### Scenario: JavaScript disabled
- **GIVEN** a browser with JavaScript disabled
- **WHEN** a page is opened
- **THEN** the navigation and endpoint content SHALL be fully readable

### Requirement: Client-side search
The site SHALL include a prebuilt search index of endpoint names, methods, paths, descriptions and parameter names, and a search box that filters it in the browser. Results SHALL appear within 100 ms for 2,000 endpoints on a typical laptop, and redacted values SHALL never be indexed.

#### Scenario: Search by path
- **GIVEN** an endpoint `GET /users/{id}`
- **WHEN** the user types `users` in the search box
- **THEN** that endpoint SHALL appear in the results

### Requirement: Dark and light themes
The site SHALL follow the browser's `prefers-color-scheme`. It SHALL offer a toggle that remembers the choice in local storage, and SHALL fall back to the system preference when storage is unavailable. Both themes SHALL meet WCAG AA contrast for body text.

#### Scenario: System dark mode
- **GIVEN** the operating system is in dark mode and no choice is stored
- **WHEN** a page opens
- **THEN** the dark theme SHALL be used

### Requirement: Deterministic output
Two builds of the same workspace, history and options SHALL produce byte-identical output. Files and navigation SHALL be sorted deterministically, the output SHALL contain no build timestamps (the version and a content hash are allowed), and line endings SHALL be `\n` on every platform.

#### Scenario: Rebuild without changes
- **GIVEN** a site built once
- **WHEN** `rustman docs build` runs again with no workspace change
- **THEN** `git diff site/` SHALL be empty

### Requirement: Markdown output
`--format markdown` SHALL write one `.md` file per section and endpoint plus `README.md` as an index, using GitHub-flavored Markdown tables and fenced code samples. It SHALL follow the same redaction, ordering and determinism rules as HTML.

#### Scenario: Markdown index
- **WHEN** the user runs `rustman docs build --format markdown --out docs/api`
- **THEN** `docs/api/README.md` SHALL link to every section file in workspace order

### Requirement: Live-reload preview
`rustman docs serve [--port 4000]` SHALL build into a temporary directory and serve it on `127.0.0.1` only. It SHALL rebuild within 1 s after a workspace file changes, and SHALL reload open pages. A busy port SHALL fail with exit code 2 naming the port. Build errors SHALL be shown in the page overlay and on stderr without stopping the server.

#### Scenario: Edit triggers reload
- **GIVEN** `rustman docs serve` running and a page open in a browser
- **WHEN** the user edits a request file's description
- **THEN** the page SHALL reload within 1 s showing the new description

#### Scenario: Port in use
- **GIVEN** port 4000 is already in use
- **WHEN** the user runs `rustman docs serve`
- **THEN** it SHALL fail with `docs: cannot bind 127.0.0.1:4000: address in use` and exit code 2

### Requirement: GraphQL and JSON-RPC reference pages
When the workspace has `graphql` requests with a cached schema from `graphql-requests`, the site SHALL add a schema reference (types, fields, arguments, deprecations). When it has `jsonrpc` requests with an OpenRPC document from `jsonrpc-requests`, it SHALL add method pages (params, result, errors). These pages SHALL be omitted when the capability or cache is absent.

#### Scenario: GraphQL schema present
- **GIVEN** a `graphql` request whose endpoint has a cached schema with type `User`
- **WHEN** docs are built
- **THEN** a reference page for `User` SHALL list its fields and their types

#### Scenario: Capability absent
- **GIVEN** a workspace without `graphql` requests
- **WHEN** docs are built
- **THEN** no GraphQL section SHALL be generated

### Requirement: Other request kinds
Requests of kinds without a dedicated renderer SHALL get a generic page listing their request-file fields as a table (with the same redaction), so every visible request is documented.

#### Scenario: gRPC request
- **GIVEN** a `kind: grpc` request in the workspace
- **WHEN** docs are built
- **THEN** a generic page SHALL list its fields and SHALL NOT fail the build
